# Single-A100 multimodal path profile (2026-11-07)

## Scope and method

- Hardware: one NVIDIA A100-SXM4-40GB.
- Code base: retained `non_blocking=True` H2D change; the negative device-native
  mask/timestep experiment remains reverted.
- Dataset/config: `data/configs/single_a100_smoke.yaml`, `max_num_tokens=2048`.
- PyTorch Profiler schedule: wait 1, warmup 1, active 2, CPU + CUDA, shapes,
  stacks, and memory enabled.
- Trace:
  `/home/why/BAGEL/traces/multimodal_ranges_20261107/node161_307973.1794027724190289776.pt.trace.json`
- CUDA time below is the sum of correlated kernel durations. It is not an
  overlap-aware GPU wall clock. CPU operator totals are inclusive and cannot be
  added together.

The two captured steps retained the expected deterministic loss sequence:
step 2 `mse=2.6535, ce=25.3393`; step 3 `mse=2.6118, ce=16.5632`.
Global peak allocated memory was 32171.88 MiB and peak reserved memory was
33802 MiB.

Profiler instrumentation is deliberately expensive: the mean traced step wall
time was 1381.99 ms versus the profiler-free retained-code median of roughly
781 ms. Use the trace for attribution, not as the production step-time result.

Attention-mask construction performs 17 small pageable H2D copies per step in
this trace. Its inclusive CPU operators are led by `aten::index_put_` (6.30 ms
per step), followed by repeated `to/copy_/arange` work. The total mask cost is
real but only about 0.8% of the profiled step. The earlier device-native
experiment removed a subset of those transfers without improving profiler-free
step time, so another local tensor-construction tweak is not the next priority.

The VAE and ViT ranges themselves do not perform material host-device traffic;
their inputs have already moved in the H2D phase. Their cost is compute and
activation allocation, not data transfer.

## MoT routing and expert execution

The following totals include 24-layer forward execution plus checkpoint
recomputation during backward: 48 invocations per step for each range.

| MoT subpath | CPU/step (ms) | CUDA/step (ms) | Kernels/step | Max transient per invocation (MiB) |
|---|---:|---:|---:|---:|
| Route input tokens + expert RMSNorm | 59.955 | 5.123 | 1008 | 16.0 |
| Expert QKV/attention/output routing | 232.312 | 21.916 | 3984 | 31.6 |
| Two expert MLP paths | 84.532 | 16.733 | 1536 | 61.8 |

Input routing alone spends 13.78 ms over two steps in gathers (`aten::index`)
and 14.70 ms in scatter calls (`index_put_` plus `_index_put_impl_`). More
importantly, backward is dominated by scatter autograd:

- `IndexPutBackward0`: 778 calls and 469.74 ms over two steps.
- Autograd engine evaluation of the same nodes: 778 calls and 476.60 ms.
- Global index/scatter kernels are highly fragmented: 1944 index kernels plus
  1888 index-put kernels in the two-step trace.

These inclusive numbers overlap, but they identify the same source: repeated
zero-initialize, gather, expert compute, and indexed scatter patterns throughout
MoT and token assembly. This is substantially larger than the 10.8 ms/step
attention-mask construction cost.

## Memory interpretation

- Absolute allocation before these ranges is already about 21.5 GiB because
  model, gradients, and optimizer state are resident.
- VAE encode adds up to 384.6 MiB transiently; ViT adds about 94.0 MiB; the
  forward MoT range adds about 136.8 MiB.
- Backward grows by as much as 5.57 GiB and reaches 26.75 GiB allocated.
- AdamW then adds as much as 5.18 GiB and reaches the global 31.42 GiB allocated
  peak. This leaves little safety margin on a 40GB device once reserved memory
  and input-shape variation are considered.
- `positive_alloc_mib` is intentionally omitted from the tables: it measures
  allocator churn and double-counts recycled blocks, so transient/peak values
  are more actionable.

## Decision and next optimization

The next optimization experiment should target MoT gather/scatter and its
backward graph, not another attention-mask tensor placement tweak. A safe first
experiment is to isolate one layer's routing shapes and compare the current
indexed assignment with `index_copy`/permutation-based assembly, checking exact
forward output and gradients before changing the 24-layer path. The success
criteria are:

1. materially fewer `IndexPutBackward0` nodes and index kernels;
2. identical output, loss, and parameter gradients within BF16 tolerance;
3. lower profiler-free median step time across repeated A/B runs;
4. no increase in the 32171.88 MiB peak.

Mask caching is a secondary experiment only when representative data shows
repeated `(sample_lens, split_lens, attn_modes)` layouts. Caching on the tiny
repeating smoke dataset would overstate production benefit.
